# 붙임1 프로그램 설명서 — 채워 넣을 내용

2026년 업무자동화 프로그램 개발대회 제출용. **지정 서식(hwpx)의 각 칸에
이 내용을 옮겨 담는다.** 서식이 요구하는 항목 순서를 그대로 따랐다.

지정 서식은 개인정보 금지 대상에서 빠지므로, 여기에는 소속·성명·연락처를
적어도 된다. 아래 `〔 〕` 로 비워 둔 곳만 채우면 된다.

# 프로그램 개발 현황

## 사용 기술

### 개발언어 및 개발도구

- **개발언어**: Python 3.13
- **개발도구**: Visual Studio Code, Git / GitHub (형상관리), GitHub Actions
  (자동 빌드·배포)
- **실행 파일 제작**: PyInstaller (단일 exe), Inno Setup (설치 파일)
- **AI 코딩 도구**: 개발 과정에서 Anthropic Claude 를 코딩 보조 도구로
  활용하였습니다. 해결할 업무 문제의 발굴, 기능과 화면의 설계, 처리 규칙의
  판단과 검증은 개발자가 직접 수행하였습니다.

### 프로그램 구성 및 아키텍처

한 프로그램 안에서 **작은 창(위젯)** 과 **전체 화면** 두 가지를 함께 씁니다.

```
   [바탕화면 위젯]                    [브라우저 전체 화면]
   기한 임박 7건만                     목록·미리보기·수정
        │                                    │
        └────────┬───────────────────────────┘
                 │  같은 프로그램 안의 작은 서버 (127.0.0.1)
                 │
        ┌────────┴────────┐
        │   SQLite 저장소  │  ← 내 컴퓨터 안에만 있음
        └────────┬────────┘
                 │
   ┌─────────────┼──────────────┬──────────────┐
   │             │              │              │
 파일 읽기    유형 분류      기한 추출      폴더 정리
 (hwpx/hwp/   (규칙 기반)   (정규식 +      (접수번호로
  pdf/xlsx)                 함정 회피)     본문·첨부 묶기)
```

| 파일 | 하는 일 |
|---|---|
| `widget.py` | 바탕화면 위젯, 서버 기동, 자동 갱신 |
| `app.py` | 작은 HTTP 서버, 화면이 쓰는 통로, 공문 묶음 집계 |
| `ui.html` | 전체 화면 (외부 라이브러리 없이 순수 JS) |
| `store.py` | SQLite 저장. 파일 **내용**을 식별자로 삼아 이름을 바꾸거나 옮겨도 처리 상태가 따라옴 |
| `classify.py` | 업무 유형 분류, 기한·행사일 추출 |
| `extract.py` / `hwpx_view.py` | 형식별 본문 읽기. hwpx 는 표·서식까지 구조째 읽음 |
| `organize.py` | 접수번호로 본문·첨부 묶기, 제목 폴더 생성, 월별 폴더 이동 |
| `compare.py` / `screen_compare.py` / `compare_window.py` | 결재 전후 공문 비교 |
| `updater.py` | 새 버전 확인 및 자동 갱신 |

### 실행환경 및 실행방법

**실행환경**

- Windows 10 / 11 (64bit). 심사 환경(Windows 11 64bit)에서 확인
- **추가로 설치할 것이 없습니다.** Python, 한글, MS Office 모두 필요 없습니다
- 관리자 권한이 필요 없습니다 (사용자 폴더에 설치)
- **인터넷이 없어도 모든 기능이 동작합니다**

**실행방법**

1. `행정-〔팀명〕소스및실행.zip` 을 풀고 `gongmun-setup.exe` 를 실행합니다.
2. **파란 경고창이 뜹니다.** 아래 *유의사항* 을 먼저 읽어 주십시오.
3. "다음" 을 눌러 설치를 마치면 바탕화면 오른쪽 위에 작은 창이 뜹니다.
4. 처음 켜면 공문을 모아 둘 폴더를 묻습니다. 함께 드린 시연용 폴더
   (`행정-〔팀명〕데이터`) 를 지정해 주십시오.
5. 작은 창의 목록을 누르면 브라우저에 전체 화면이 열립니다.

설치 없이 `gongmun.exe` 를 바로 실행해도 동일하게 동작합니다(USB 사용 가능).

> ### ⚠️ 심사에 앞서 반드시 읽어 주십시오
>
> 실행할 때 **"Windows의 PC 보호"** 라는 파란 경고창이 뜹니다.
>
> **왼쪽 아래 "추가 정보" → "실행"** 을 누르시면 진행됩니다.
>
> 이는 코드 서명 인증서를 구매하지 않은 프로그램에 Windows 가 항상 띄우는
> 안내이며, 바이러스라는 뜻이 아닙니다. 개인이 개발한 프로그램으로 연간
> 수십만 원의 인증서 비용을 부담하기 어려워 서명하지 않았습니다.
> 같은 이유로 일부 백신이 오탐할 수 있습니다.
>
> 제출 전 최신 백신으로 검사를 완료하였습니다.

### 입력·출력 파일 형식

**입력** — 에듀파인에서 내려받은 공문 파일을 폴더에 넣기만 하면 됩니다.

| 형식 | 읽는 정도 |
|---|---|
| `.hwpx` | 표·들여쓰기·정렬까지 구조 그대로 (가장 정확) |
| `.hwp` | 본문 문단. 표 안의 글자도 대체로 읽힘 |
| `.pdf` | 글자가 들어 있는 PDF (공문 본문이 보통 이 형식) |
| `.xlsx` `.xls` | 시트별로 나누어 읽음 (제출 서식에 많음) |
| `.docx` `.txt` | 본문 |
| 그 밖(zip, png 등) | 내용은 읽지 않되 **같은 접수번호면 한 묶음으로 함께 정리** |

**출력**

- 화면: 기한순으로 정렬된 목록, 본문 미리보기, 기한 근거 문장
- 파일: `일정 내보내기` 로 `.ics` 생성 (구글 캘린더 등에서 가져오기)
- 폴더: `폴더 정리` 로 제목 폴더 생성, `완료된 업무 정리` 로 월별 폴더 이동
  (**어떤 경우에도 파일을 지우지 않으며, 옮기기 전에 무엇이 어디로 가는지
  먼저 보여 주고 확인을 받습니다**)

### 주요 오류 발생 시 조치 방법

| 증상 | 조치 |
|---|---|
| 파란 경고창이 떠서 실행이 안 됨 | "추가 정보" → "실행" |
| 작은 창이 안 보임 | 바탕화면·시작 메뉴의 "공문 정리함" 을 **한 번 더** 실행하면 숨어 있던 창이 앞으로 나옵니다 (작업 표시줄에는 뜨지 않는 창입니다) |
| 목록에 공문이 안 나옴 | 작은 창의 `다시 훑기`. 폴더가 맞는지는 창 제목 아래 폴더 줄을 눌러 확인 |
| 종류·기한이 잘못 잡힘 | 전체 화면에서 직접 고치면 **고친 값이 항상 우선**하며 다시 분석해도 지워지지 않습니다 |
| 암호 걸린 파일 / 스캔 PDF | 글자가 없어 읽지 못합니다. 목록에는 뜨고 "미분류" 로 들어갑니다 |
| 그 밖의 오류 | 안내창과 함께 `사용자 폴더\.gongmun\오류기록.txt` 에 기록이 남습니다 |

### 향후 수정이 필요한 주요 설정값

| 값 | 위치 | 뜻 |
|---|---|---|
| `_RULES` | `classify.py` | 업무 유형 판단 키워드와 가중치. 학교에서 자주 쓰는 표현을 넣으면 정확도가 오릅니다 |
| `_DEADLINE_CUES` | `classify.py` | 기한으로 볼 표현 |
| `_STALE_DAYS` (400) | `classify.py` | 이보다 오래 지난 날짜는 기한으로 보지 않음 |
| `_INBOX_NAMES` | `organize.py` | 공문 폴더로 인정할 이름 (`공문`, `접수공문` 등) |
| `REFRESH_MINUTES` (10) | `widget.py` | 폴더를 다시 훑는 주기 |
| `UPDATE_GAP_HOURS` (4) | `updater.py` | 새 버전 확인 주기 |

### 프로그램에서 사용하는 외부 시스템 또는 기능

**업무자료를 바깥으로 보내지 않습니다.** 공문 내용, 파일 이름, 폴더 경로가
외부로 나가는 일이 없습니다. 외부 API·AI·클라우드를 일절 쓰지 않습니다.

바깥으로 나가는 통신은 **새 버전이 있는지 확인하는 것 하나뿐**이며, 모두
GitHub 으로만 갑니다.

| 언제 | 어디로 | 보내는 것 |
|---|---|---|
| 켤 때, 이후 4시간마다 | `github.com/.../releases/latest` | 없음 (버전 번호만 받음) |
| 새 버전이 있을 때만 | `api.github.com` | 없음 (설명글만 받음) |
| 이용자가 갱신을 수락했을 때만 | `github.com/.../releases/download` | 없음 (실행 파일만 받음) |

인터넷이 없거나 차단된 환경에서도 **모든 기능이 그대로 동작하며**, 버전
확인만 조용히 건너뜁니다. 이 동작은 회귀 테스트로 고정해 두었습니다
(`tests/test_judging.py`).

**보안 관련 설계**

- 화면을 여는 작은 서버는 **`127.0.0.1`(내 컴퓨터) 에만** 열립니다. 다른
  컴퓨터에서 접근할 수 없으며, 그래서 **Windows 방화벽이 허용 여부를 묻지
  않습니다.** 랜 주소로 접근되지 않는 것을 시험으로 확인합니다.
- 계정·비밀번호·인증정보를 저장하거나 요구하지 않습니다.
- 업무시스템의 보안 기능이나 접근통제를 우회하지 않습니다.
- 모든 자료는 `사용자 폴더\.gongmun\` 안의 SQLite 파일에만 저장됩니다.
- 결재 전후 비교에서 찍은 화면은 **메모리에만 두며 파일로 저장하지 않습니다.**

# 현행 업무 및 개선 내용

## 현행 업무 방식

교사는 에듀파인에서 공문을 내려받아 처리합니다. 그런데 공문은 **부서를
기준으로** 작성되어 있어, 받는 사람이 다음을 스스로 가려내야 합니다.

1. **이 공문이 나에게 할 일을 주는가, 그냥 알아 두면 되는가**
2. **언제까지인가** — 기한은 본문에 있기도 하고, 첨부된 계획서나 제출
   서식에만 적혀 있기도 합니다
3. **어느 것이 급한가** — 받은 순서와 급한 순서는 다릅니다

여기에 더해 실무에서 시간을 많이 쓰는 일이 셋 있습니다.

- **본문과 첨부가 따로 내려받아집니다.** 한 공문이 파일 서너 개로 흩어져
  어느 것이 한 건인지 매번 확인해야 합니다.
- **처리한 공문을 정리해 두어야 합니다.** 대개 월별 폴더로 옮기는데,
  손으로 옮기다 보면 미루게 되고 나중에 찾기 어려워집니다.
- **결재자가 말없이 고쳐서 결재합니다.** 무엇이 바뀌었는지 알려면 원본과
  결재본을 나란히 놓고 눈으로 훑어야 합니다.

결국 **"받은 공문을 다시 읽어 내 할 일로 옮겨 적는 일"** 을 사람이 반복하고
있으며, 이 과정에서 기한을 놓치는 일이 생깁니다.

## 업무자동화 프로그램을 이용하여 개선된 방식

### 주요 기능

**① 폴더에 넣기만 하면 됩니다**

에듀파인에서 받은 파일을 공문 폴더에 저장하면, 프로그램이 알아서 읽어
**기한이 가까운 순서로** 목록을 만듭니다. 따로 입력하거나 옮길 것이 없습니다.

**② 부서가 아니라 "내가 할 일" 기준으로 나눕니다**

제출·보고 / 일정·행사 / 신청·공모 / 배포·전달 / 안내·참고 다섯 가지로
나누고, 색 띠로 구분해 보여 줍니다. 잘못 잡으면 화면에서 바로 고칠 수 있고
**고친 값이 항상 우선**합니다.

**③ 기한을 본문에서 찾아냅니다 — 첨부까지 뒤져서**

`제출 기한: 9. 30.(수)까지` 같은 표현을 찾아 마감일로 잡습니다. 실제
공문에는 함정이 많아 다음을 모두 걸러 냅니다.

- 결재선의 `시행 … 접수 …` 날짜
- `1. 관련: OO과-14453(2026. 7. 31.)` 처럼 다른 공문을 인용한 날짜
- 규정 부칙의 오래된 시행일
- `신청 9.18.까지 / 일시 9.24.` 처럼 마감과 행사일이 섞인 문장

**기한이 본문이 아니라 첨부 계획서에만 적혀 있는 경우가 많아, 본문과 첨부를
모두 살펴 가장 이른 날짜를 씁니다.** 이 판단 규칙은 실제 공문에서 틀렸던
사례를 그대로 시험 케이스로 만들어 고정해 두었습니다.

**④ 본문과 첨부를 한 건으로 묶습니다**

파일 이름 앞의 접수번호(`[○○중학교-4971]`)로 흩어진 파일을 한 공문으로
묶습니다. 내용을 읽을 수 없는 zip·png 첨부도 같은 접수번호면 함께 묶어
빠뜨리지 않습니다. `폴더 정리` 를 누르면 공문 제목을 딴 폴더를 만들어
정리해 줍니다.

**⑤ 끝난 일은 월별 폴더로**

`완료된 업무 정리` 를 누르면 마감일이 속한 달의 폴더로 옮깁니다. **읽는 곳은
공문 폴더 한 곳뿐이며, 월별 폴더의 내용은 절대 읽지 않습니다** — 그 안에는
개인정보나 다른 업무 파일이 섞여 있기 때문입니다.

**⑥ 결재 전후 비교**

기안한 공문과 결재된 공문을 나란히 띄워 두고 영역을 끌면, 달라진 곳을
빨간 상자로 표시합니다. 글자를 읽는 것이 아니라 모양을 견주므로 한글이든
PDF든 화면에 보이기만 하면 됩니다.

### 활용 방안

- **개인**: 공문 폴더를 지정하는 것만으로 바로 쓸 수 있습니다.
- **학교**: 업무 폴더 구조(`○○기획 / 공문 / 월별`)를 그대로 따르므로,
  기존에 쓰던 방식을 바꾸지 않고 얹을 수 있습니다.
- **교육청**: 설치 파일 하나로 배포 가능하며, 자동 갱신이 있어 이후 개선을
  이용자가 따로 내려받지 않아도 됩니다.

### 기대 효과

| 지금 | 이 프로그램으로 |
|---|---|
| 공문을 열어 읽고 할 일과 기한을 옮겨 적음 | 폴더에 넣으면 목록이 만들어짐 |
| 기한이 첨부에만 있으면 놓치기 쉬움 | 본문·첨부를 모두 살펴 가장 이른 날짜 |
| 한 공문이 파일 서너 개로 흩어짐 | 접수번호로 한 건으로 묶임 |
| 처리한 공문 정리를 미루게 됨 | 단추 한 번으로 월별 폴더에 정리 |
| 결재자가 고친 곳을 눈으로 찾음 | 달라진 곳을 표시해 줌 |

가장 큰 효과는 시간 절약보다 **놓치지 않는 것**에 있습니다. 공문을 하루에도
여러 건 받는 상황에서 기한을 놓치면 개인의 일로 끝나지 않고 학교 전체의
업무가 밀립니다.

또한 이 프로그램은 **한 사람이 실제로 쓰면서 고쳐 온 도구**입니다. 실제
사용 중 나온 오류를 재현하고 수정한 뒤 회귀 테스트로 고정하는 과정을
반복했으며, 그 기록이 모두 공개 저장소에 남아 있습니다.
